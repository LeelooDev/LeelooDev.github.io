> 学大模型开发最常见的状态是：收藏夹里躺着几十份教程、网盘里存着好几门课，可每天打开电脑还是不知道现在该学什么。问题从来不是资料不够，而是没有一条带**验收标准**的路线——你分不清自己是「学过了」，还是「学会了」。这篇文章把整条路拆成十步、四个阶段，每一步后面都跟着一条可以自测的标准：达标了再往前走，不达标就停在原地补课。

## 一、学得散，比学得慢更致命

慢不可怕。一步一个脚印，哪怕走一年，走到头就是一个能跑在线上的 Agent 项目。散才可怕：今天看微调、明天玩新模型、后天又被某个框架的发布会带走，每样都摸过，没有一样能拿出来。

解药很朴素，就两条：

- **顺序**：先地基后原理，先原理后应用，先应用后交付。跳步的代价不会消失，只会在后面加倍偿还——Prompt 调不好的人，多半是第 3 步的直觉没建立；RAG 讲不清选型的人，多半是第 2 步的数据功底没打牢。
- **验收**：每一步都用「能做出什么」来度量，而不是「看完了什么」。看完十小时视频不算学会，能用 Pandas 把一份脏 CSV 清洗干净才算。

下面这张表就是全部路线，可以先收藏，再往下看每一步的展开。

## 三、第一阶段：打好地基（第 1–2 步）

编程和数据是所有 AI 工作的底色。这一阶段不追求高深，追求扎实。

### 第 1 步：Python 基础

变量、控制流、函数、类、异常处理，再加上虚拟环境和包管理。这一步的目标不是成为 Python 高手，而是两件事：**能读懂别人的代码，能写出自己的脚本**——后面九步全部建立在这上面。

最常见的误区是死磕语法：把生成器、元类、装饰器的每个细节都啃一遍才敢往前走。不必。写起来，遇到不会的再查，比通读语法书快得多。

> **验收标准**：能独立写出一个带函数、类和异常处理的小工具脚本，会用 venv 和 pip 管理项目依赖。

### 第 2 步：数据处理三件套——NumPy、Pandas、Matplotlib

真实业务里的数据永远是脏的：缺失值、重复行、格式混乱的日期、藏在字符串里的数字。NumPy 负责数值计算，Pandas 负责清洗和分析，Matplotlib 负责把结论画出来。

别把这一步当成「传统数据分析的遗产」跳过去——到了第 5 步做 Prompt 评测、第 8 步算工具调用准确率时，你每天都在用 Pandas 处理实验结果。数据功底就是在这里攒下的。

> **验收标准**：能用 Pandas 清洗一份 CSV 文件，完成缺失值处理、分组聚合等基本统计分析。

## 四、第二阶段：看懂原理（第 3–4 步）

不求手推公式，但要建立正确的直觉：大模型不是魔法，是训练出来的。这一阶段决定了你之后是「会用大模型」还是「理解大模型」。

### 第 3 步：深度学习基础

神经网络、损失函数、梯度下降、反向传播。目标不是做算法研究，而是在脑子里建立一条完整的链路：**数据进来 → 前向计算 → 算出损失 → 反向传播 → 更新参数**。

有了这条链路，后面遇到微调、过拟合、幻觉这些概念时你不会一头雾水；没有它，大模型对你就永远是一个黑盒，出了问题只能靠猜。

> **验收标准**：知道模型是怎么训练出来的——能用自己的话讲清楚「前向传播 → 损失 → 反向传播 → 参数更新」这条链路。

### 第 4 步：Transformer 架构

所有主流大模型的骨架。重点搞懂三件事：自注意力机制（Self-Attention）在做什么、位置编码为什么必须存在、Encoder 和 Decoder 各自的角色。

不需要从零手写一个 Transformer，但注意力机制那张经典结构图，你应该能指着它给别人讲明白。

> **验收标准**：能看懂注意力机制的结构图，并说清楚 Q、K、V 各自在做什么。

## 五、第三阶段：学会应用（第 5–8 步）

从 Prompt 到 Agent，这是大模型应用工程师的核心技能区，也是真正拉开差距的地方。

### 第 5 步：大模型基础与 Prompt 工程

先补齐应用层的基础概念：上下文窗口、token、温度、few-shot、结构化输出。然后是这一步的重点——把 Prompt 当工程做，不当玄学玩。

区别在哪？玄学的做法是改两句话、跑三个例子、「感觉回答得不错」就收工；工程的做法是先攒一个测试集，每改一版 Prompt 就在测试集上跑一遍，用准确率说话。90% 不是一个随口说的数字，它是「这个 Prompt 能不能进业务」的门槛。

> **验收标准**：能在真实业务场景里设计出准确率大于 90% 的 Prompt——用测试集量出来的 90%，不是感觉。

### 第 6 步：LLM 开发框架

以 LangChain 为代表的开发框架，解决的是模型调用、链路编排、对话记忆这些工程问题。框架本身不难，一周就能上手；难的是理解**它替你封装了什么**——底层无非是拼接上下文、调用 API、解析输出。想明白这一点，将来换框架、甚至不用框架裸写，你都不慌。

> **验收标准**：能用 LangChain 搭建一个可以连续对话的简单问答机器人。

### 第 7 步：RAG 检索增强

让模型基于你的知识库回答问题，而不是凭训练时的记忆瞎猜。整条管线是：文档切分 → 向量化 → 检索 → 重排 → 生成，每一环都有取舍。

「企业级」和「demo 级」的差距不在代码量，而在你能不能回答这些问题：为什么这样切分？为什么选这个向量库？检索质量怎么量化？坏答案出现时，怎么定位是检索的锅还是生成的锅？跑通一个 RAG demo 只要一下午，能回答上面这些问题才算过关。

> **验收标准**：能独立搭建一套企业级 RAG 系统，并说清楚每个环节的选型理由和检索效果。

### 第 8 步：Agent 开发

工具调用、任务规划、多步执行、失败重试。Agent 是当前含金量最高的方向，也是最容易做成花架子的方向——衡量标准只有一个：**工具调对了没有，任务完成了没有**。

Agent 的错误是会累积的：每一步的输出都是下一步的输入，单步 95% 的准确率，二十步下来任务成功率只剩三成多。所以「调用准确率高」不是锦上添花，它直接决定这个 Agent 能不能用。评测方法沿用第 5 步：测试集 + 准确率，数字说话。

> **验收标准**：能开发一个调用多个工具完成复杂任务的 Agent，且工具调用准确率经过评测验证、稳定在高水平。

## 六、关键分水岭：为什么「会调 API」不再是竞争力

走到这里要先停一下，聊一个比「学什么」更重要的问题。

两年前，能调通 OpenAI 的 API 就算入门了 AI；今天，这只是起跑线。市面上最不缺的就是「套壳机器人」——接一个 API、包一层界面、什么都能聊两句、什么问题都解决不了。把这样的项目写进简历，面试官两个问题就能问穿。

真正缺的，是**能落地、能量化、能维护**的 Agent 项目。一个拿得出手的 Agent 项目，必须同时具备三样东西：

**其一，明确业务场景 + 工具调用。**不是「什么都能聊」，而是解决一个具体问题：Agent 能正确调用查询、计算、写入等真实工具，完成端到端的业务动作。场景越具体，项目越有说服力。

**其二，RAG 检索增强 + 可观测日志。**回答有依据、可溯源，而不是凭模型想象；每一次调用链路都留有日志，出了问题能定位到具体哪一环。没有可观测性的 Agent，坏了你连它为什么坏都不知道。

**其三，错误处理 + 自动化评测 + 可部署 Demo。**工具失败会重试和降级；有评测集持续跑准确率，效果用数字说话；最后给面试官或客户一个点开就能用的链接。

这三条是一个整体：少一条，项目就退化成 demo 玩具；三条齐，才是能写进简历、经得起追问的工程作品。它们也正是下一阶段实战项目的需求规格——第 9 步做什么，标准已经在这里了。

## 七、第四阶段：交付上线（第 9–10 步）

从「会做」到「能交付」。没有上线的项目，写在简历上说服力减半。

### 第 9 步：项目实战

把第 5–8 步的能力揉进一个真实业务场景，按上一节的三要素做出完整闭环：需求分析、技术选型、开发、评测、迭代。

选题宁小勿大。一个把小问题解决透的项目——比如给某个具体行业做一个能查数据、能算指标、能出报告的助手——远胜一个什么都沾一点的大杂烩。做完之后，你应该能讲清楚三件事：业务价值是什么、技术为什么这么选、效果数据是多少。

> **验收标准**：完成一个解决真实问题的项目，能讲清楚业务价值、技术选型和量化的效果数据。

### 第 10 步：部署上线

Docker 容器化、API 服务、日志监控、成本控制。上线不是终点，而是把项目从「代码」变成「产品」的最后一公里——也是面试时最能证明工程能力的一环。能把服务稳定跑在线上的人，和只会在本地跑 notebook 的人，在面试官眼里是两个物种。

> **验收标准**：能把项目部署到服务器，提供一个稳定、可公开访问的在线 Demo。

## 八、写在最后

这条路线没有捷径，但有清晰的验收点。它最大的价值不在「十步」本身，而在每一步后面那条标准——它逼你诚实：到底是「学过了」，还是「学会了」。

不用等准备好了再开始。从第一步起，把验收标准一条一条打上勾。走到第十步时，你手里就不只是一堆教程笔记，而是一个跑在线上的、有业务价值的、经得起追问的 Agent 项目。
