一个能调用工具的 Agent，最重要的不是“会不会自主规划”，而是每一步是否可观察、可取消、可重试。

## 工具契约

每个工具都应该明确：

- 输入字段、默认值和上限。
- 是否只读，是否会产生外部副作用。
- 超时、重试与幂等语义。
- 失败时返回给模型的可操作信息。
- 哪些动作必须经过用户确认。

工具描述要告诉模型什么时候不应该调用它。只有正向说明，很容易让 Agent 在不确定时过度尝试。

## 循环预算

```python
budget = {
    "max_steps": 12,
    "max_tool_calls": 20,
    "deadline_seconds": 90,
}
```

达到预算后返回已完成内容、未完成内容和最后一个可靠状态，而不是继续用新的工具调用掩盖失败。

## 写操作三道闸

1. **计划闸**：先明确目标、对象和影响范围。
2. **确认闸**：删除、发布、付款、发送消息等动作在执行点确认。
3. **验证闸**：写入后读取权威状态，不能只相信工具返回的“成功”。

## 日志最小集合

记录 run ID、step、工具名、耗时、输入摘要、结果摘要、错误类别和 token 使用量。敏感信息要在进入日志前脱敏。

当护栏、预算和状态验证都清晰后，Agent 的“自主性”才会变成可交付的工程能力。
